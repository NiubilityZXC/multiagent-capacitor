# 全量重叠审计后的目标资格最短路径

2026-09-20。实现规划，不是 pre-run release、标签生成授权或 Data Gate PASS。沿用 REN_R1F_REMAINING_EVIDENCE_20260914.md；不修改 R2、原始输入或冻结评测计划。

## 已有接口的限制

现有 overlap spool 只保留 status、局部时间、V、mA、mAh 与可选 energy，以及组级 source spans；投影刻意排除 cycle/step/record_number。它不能独自完成逐 cycle/step 的容量资格审计。不得从时间归零猜测 cycle，或以整组相似度替代步级证据。

## 下一新增审计器应一次采齐的证据

1. 复用已审 Workbook-only 容器边界、固定 schema、时钟解析与记录完整性检查，不改动冻结模块。对每个设备候选组完整消费所有分片；sheet/文件边界不能重置正在累计的工步。
2. 以 native `(cycle, step, status)` 识别连续工步段，保留首末 record_number、局部时间、V、I、mAh、行数及原始位置；记录时间回退、同时间多记录、电流符号/范围、充放电电压方向与非有限值。不得输出 F、SOH 或 RUL。
3. 对照主文件 step 表的同一 key：持续时间、末端 mAh/energy；若源 schema 有 ini/end voltage，再与记录端点逐项对照。batch1 缺少 step 电压端点，显式记缺失，不补零，不沿用作者特殊修补。
4. 对照 cycle 表的 charge/discharge capacity 与各工步记录；处理一周期多个充电工步的证据时保留全部成员。禁止直接取第一条 status 行、用字典覆盖重复 key，或把 mAh 改名 F。
5. 记录实际充电工况及放电电流证据，再对照论文的恒流/阶梯描述。名义 20 mA 与实测电流必须分开；先记录误差分布，不查看后临时挑容差或删掉不合意设备。
6. 单独登记最后完整/不完整 cycle、原生终止原因是否存在；最后记录不等于失效。没有可核验事件时，RUL 不合格不应自动否定容量轨迹任务。

## 在读取真实数据前完成

- 纯函数及小型合成 Workbook 测试：跨表跨片工步、两种 step/cycle 布局、阶梯充电、重复/遗漏 summary key、额外行、浮点/文本类型混淆、非有限值、非单调时间、截断尾周期、缺失端点；不以通过数量代替断言质量。
- 独立重建字段与端点 join，明确哪些是严格结构错误、哪些只是尚待解释的测量差异。独立 reviewer 检查整体调用链后才生成新 release，真实输出另建 append-only 目录。
- 不重新下载、解压或执行作者 preprocess；不调用 API、模型或 GPU。新扫描先最小样本 sanity，再按批准边界全量，终止回执和完整对账后才裁决资格。

## 实验开跑关口

先完成 R2 独立运行后审查及匹配解释，再把上述目标证据与来源身份、重复关系结合，冻结 whole-unit 与工况切分。随后才产生新的 P2 数据/target/eval seal 并按既有规则放行数值基线。

这不是新增研究方向或无限加门槛：目标、身份、终止与切分原本就是 P1 要求。是否出现需要人工裁决的真实冲突，由证据决定；不能承诺“再固定几个命令就必过”。
