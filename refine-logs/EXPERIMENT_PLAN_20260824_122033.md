# Experiment Plan: Hybrid-Agent Capacitor Forecasting v0.3

**Problem**：判断通用大模型 Agent 是否能在严格因果在线回放中，通过路由/融合专用数值小模型，提高未见电容的 C/ESR 多步预测精度。  
**Method Thesis**：小模型负责数值外推，LLM Agent 只做受约束的 regime diagnosis、candidate criticism 与 convex routing；任何失败都回退到训练侧冻结的小模型。  
**Date**：2026-08-24  
**Status**：H-A0 complete；真实 API H-A1/H-A2 等待人工检查点；Benchmark-L 模型继续等待 target-specific Data Gate。

|---|---|---|---|
| H1 Hybrid utility | 证明 LLM 对真实数值精度有增量，而非仅提供解释 | A2 在同 model/input/budget 下同时优于最强单小模型 C1、无 LLM 融合 C2 和 direct LLM A1；单位级、最坏工况、失败率与区间门均通过 | B2, B3 |
| H2 Topology necessity | 证明多 Agent 复杂度确有必要 | A3 优于 A2 后才比较 A4/A5；相同 token/call/wall-clock 预算；负结果选择更简单拓扑 | B4 |
| Anti-claim | 排除更多 token、未来泄漏和 Agent 自评导致的假提升 | suffix invariance、planned-key parity、训练侧 calibration、公共 fallback、预算配平、数值 scorer | B0–B5 |

## Experiment Blocks

### B0：无网络合同与故障闸门

- **Claim**：Anti-claim。
- **Systems**：strict causal request、三角色、四拓扑、ArkCLI dry-run adapter。
- **Tests**：tainted key、wrong origin、extra field、NaN/Inf、非法权重、timeout/429/5xx、并发顺序、convex hull、公共 fallback、secret/argv。
- **Success**：全部测试通过；dry-run 明确 network blocked；真实 key 不进入 argv/log。
- **Status**：COMPLETE，64 tests 全套通过，其中 hybrid 13 tests。
- **Priority**：MUST。

### B1：方舟 capability smoke

- **Claim**：接入可用性，不测试精度。
- **Input**：一个完全合成 OriginPacket，无公开数据或标签。
- **Model**：Kimi-K3 logical ID；记录服务返回具体 model/version。
- **Checks**：strict JSON、schema compliance、tools none、cache disabled、no store、usage、latency、deadline、fallback。
- **Success**：一次合法响应或可解释 fallback；无 secret 泄漏。
- **Failure**：保持 H-A2 blocked，先修接口。
- **Priority**：MUST / HUMAN GATE。

### B2：最小真实数值对照（Stress-2 shadow）

- **Claim**：只验证 H1 的可执行性，不形成可发表冠军。
- **Split**：现有 nested column-surrogate LOCO；严格 rolling origin；common planned keys。
- **Arms**：C0 last value、C1 inner-LOCO best expert、C2 numeric convex fusion、A1 direct LLM、A2 single-agent hybrid。
- **API budget**：先每列一个冻结 origin；每 arm 一个 API replicate。通过后才扩展全部 origins 与预注册 repeats。
- **Metrics**：unit-macro MAE/RMSE/MASE/skill；invalid/fallback；token/call；p50/p95 latency。区间为 NA（独立 calibration units 不足）。
- **Success**：causal/ledger/scorer/失败路径全部通过。Observed ordering 仅 descriptive。
- **Priority**：MUST / SANITY ONLY。

### B3：Benchmark-L 主比较

- **Claim**：H1。
- **Eligibility**：capacity 需 G00–G07、G10；ESR 另需 G08；物理 ID/duplicate group、Design Gate、Freeze B 全通过。
- **Split**：先 condition 内 physical-unit LOCO；LOVO 单列 transfer estimand。
- **Arms**：C0/C1/C2/A1/A2；GPR/TSFM 只能 add-one 且先过 sample/compute gate。
- **Primary**：Freeze B 的 unit-macro MAE；支持指标、配对单位差与非劣门按协议。
- **Success**：A2 同时超过 A1、C1、C2 的最小有意义改善，且 coverage/failure/worst-condition 合格。
- **Failure**：接受 C1/C2；不进入多 Agent。
- **Priority**：MUST-CONDITIONAL。

### B4：拓扑必要性

- **Claim**：H2。
- **Run order**：A3 fixed hierarchy；若胜 A2，再比较 A4 parallel debate；若静态多 Agent有效，再比较 A5 dynamic route。
- **Fairness**：同 Kimi-K3、同 packet、专家库、fallback、API repeats；token/call/wall-clock 上限配平。
- **Success**：预注册 paired unit loss 达标，同时 API failure 与 latency 非劣。
- **Failure**：选择更简单拓扑并停止。
- **Priority**：CONDITIONAL。

### B5：校准、失败与边界

- **Intervals**：每 arm 自己的 outer-train inner-LOCO residual calibration；LLM 不生成区间。
- **Faults**：invalid JSON、timeout、429/5xx、迟到响应、missing expert、API model drift、session contamination。
- **Diagnostics**：按 origin 的 route、weights、candidate disagreement、fallback、latency、token 与实际 error；不以 LLM 理由评分。
- **Priority**：MUST for any formal claim。

## Compute and API Budget

- H-A0：CPU-only；无网络推理。
- H-A1：最多 2 次调用（一次合法请求；只有网络级错误允许一次重试）。
- H-A2 subset：先 6 个 origin；不跑全量拓扑矩阵。
- Formal：冻结 input/output token、call、wall-clock 与 API replicate；至少 5 个完整 API repeats 仅在 Design Gate 证明可辨识时执行。
- 真实价格不猜测；账单/usage 证据与预测 ledger 分开绑定。

## Risks and Mitigations

- **LLM 数值能力弱**：A1 为对照；主 Hybrid 只在候选凸包内融合。
- **近邻过强/新颖性低**：不主张通用 router 新颖；聚焦电容 causal graph、failure-safe Eval 与真实效果。
- **API model drift**：冻结 logical ID 与服务返回 version；不匹配即 fallback/新版本 arm。
- **密钥已出现在对话**：真实调用前轮换；只从环境变量读取。
- **Stress-2 伪独立**：只能 sanity；不做推断或 champion。
- **Benchmark-L target blocked**：模型调用保持禁止，直到 target-specific gate 通过。
- **多 Agent 仅增加成本**：阶段门失败即停，保留单 Agent/数值系统。
