## 4. 为什么不能直接把数据喂给 Agent

### 4.1 预测目标可能叫错名字

原始表中存在 mAh、mWh、V、mA、局部时间等字段。mAh 是电荷量口径，F 是电容口径；仅把字段改名不能完成物理量转换。还要核实对应的充放电工步、电压区间、积分/端点含义以及采样是否完整。

SOH 同样需要冻结定义：相对额定值，还是相对某个初始测量值，不能混用。若目标定义不成立，模型即使预测得很“准”，也可能是在预测错误命名的量。

### 4.2 已经发现真实重复风险，不只是理论防备

`batch3/22` 与 `batch3/23` 各有 1,523,379 行。其保存的测量投影完全相同；投影含 status、局部时间、V、mA、mAh、energy，但不含全部 native key 和工作簿内容。源容器与 Workbook 哈希又不相同。

这不能直接证明同一个物理器件，也不能当作独立样本无事发生。若高度重复数据被放进训练和测试两边，结果可能看起来很好，却无法证明跨器件预测能力。需要依据来源、native key 与完整工步证据裁决，并在看模型结果之前固定处理和切分方式。

### 4.3 数据有分片、不同表布局和多工步

一个命名组可能跨多个 XLS 文件；工步可能跨表、跨文件。若每打开一个文件就重置累计状态，或者一个周期只取第一条充电记录，可能漏算、重复计算或选错端点。batch1 缺少某些电压端点列，也不能默认补零。

### 4.4 最后一次记录不等于失效

测试结束、文件截断和达到失效阈值是不同事件。没有可核验的失效事件，就不能把最后记录机械定义成 RUL=0。

**这不要求等所有任务都能做才开始研究：Ren 的 ESR 目前固定 NA；RUL 独立判断资格，不应因为 RUL 不成立就无限阻止合格的容量轨迹预测。**

### 4.5 在线预测容易在不知不觉中看到未来

滑动窗口、归一化、特征选择、融合权重、预测区间校准和模型选择都必须只使用允许的训练数据及当时可见的历史。设备级留出、滚动回放和标签到期后再评分，用来防止“回头看完整曲线，再假装在线预测”。

## 5. 各类检查各自解决什么问题

| 检查 | 要避免的具体错误 | 完成边界 |
|---|---|---|
| 来源/文件校验 | 读取了不同版本、漏了分片、顺序不对 | 已有冻结来源和完整覆盖可复用；不是每轮重新下载或解压 |
| 解析和单位核验 | 错列、错单位、跨片重置、缺失值补零 | 组件已审；需在完整入口验证真实目标资格 |
| 独立字段重建 | 生产代码算错，但用同一结果检查自己仍“通过” | 独立派生计算与持久化逐字段核对；不宣称超出共享解码边界的独立性 |
| 重复和设备级切分 | 训练/测试重复、有效样本量虚高 | 处理已发现的一对冲突并冻结切分；无需重跑已完成的全量重叠扫描 |
| 合成/对抗测试 | 常规输入能跑，缺片、篡改或异常退出时却报成功 | 检查会发生的失败路径，不以不断增加测试数量作为结束条件 |
| 独立 pre-run review | 单个模块都对，但入口、环境、预算和退出回执接错 | 完整入口审查通过后放行真实 sanity；不把组件通过当成整套通过 |
| 正式 Eval 和封存 | 看结果挑阈值、删坏样本、反复调测试集 | 实验前固定，最后以数值结果决定论文能说什么 |

文件哈希和审查记录只能支持来源与执行可追溯，不能证明物理语义正确，更不能证明模型准确。

## 7. 为什么花了这么久：科研原因和工程损耗要分开

必要的科研问题是：目标物理定义、真实重复关系、有效器件数、时间因果约束和留出切分。这些直接影响精度是否可信。

但不是所有耗时都属于必要科研。已经发生的额外损耗包括：测试夹具写错、不同虚拟环境依赖不一致、解析异常路径资源释放问题、早期审查脚本自身错误、工具额度中断，以及另一会话留下未完成草稿。它们属于实施或运行问题，不能包装成“又完成了一项科学发现”。

此前逐个组件实现、审查、再汇报的节奏也延长了端到端交付时间。后续应集中完成完整入口和一次整体审查，修复具体阻断；不重复已经完成的 archive/schema/chronology/overlap，也不为非阻断文档问题重新开启全量扫描。额度中断不能记作测试通过。

## 8. 从现在到真实预测实验的有限路径

1. **入口完成**：保留并发草稿原件，修复接口与测试，补齐完整持久化、覆盖、失败回执和预算约束；做整体独立 pre-run review。
2. **真实资格审计**：先最小真实 sanity，再按批准范围全量执行，核对退出回执和持久化结果；不重做旧重叠审计。
3. **Data Gate 裁决**：用实际证据确定可用 target、重复对处理、末端/删失和器件级切分。若容量任务合格而 ESR/RUL 不合格，明确缩小任务，不能捏造标签。
4. **P2 数值实验**：固定数据/target/Eval，运行冻结专用模型基线、滚动回放与 whole-unit 验证，校准指标和区间，检查统计功效。
5. **P3/P4/P5 大模型实验**：安全凭据与能力/预算 Gate，随后运行直接 LLM、LLM+专用模型及多调用对照。旧聊天中暴露的密钥不写入代码或 Git；能力探测不等于精度验证，正式 API 支出仍遵守冻结人工批准范围。
6. **结果到论文**：根据真实结果做预定统计、消融、结论审查和论文写作。正/负/空结果均如实报告，不以 LLM 主观分数代替误差，也不保证一定达到高水平发表门槛。

这是带完成条件的工作路径，不是“再点固定几次继续就必过”。当前不能提供可靠的开跑日期：还缺真实容量资格结果；此前“1–2 天”只能理解为条件成立时的有效工作量估计，不是已经兑现的日历承诺。
