## Blocking-condition recheck

1. **One canonical joint-unseal artifact: PASS.** `issue_generation_joint_unseal_authorization` accepts only a normalized absolute path exactly equal to `<frozen-plan-parent>/GENERATION_JOINT_UNSEAL.json`. Publication uses a regular-directory check, `O_EXCL | O_NOFOLLOW`, canonical bytes, file `fsync`, and directory `fsync`; alternate filenames and repeat publication fail closed.

2. **Exact complete admitted supervisor/cell/session set: PASS.** The plan's formal cells are exactly the Cartesian product of every `ADMITTED` arm and fold. Joint issuance requires the supplied formal bindings to have the same plan, barrier, and plan hash; the supplied cell-ID set must equal the complete plan-cell set with no duplicate supervisor binding. Every supervisor must be live and must revalidate its formal launch binding. `GenerationJointUnsealAuthorization` additionally rejects duplicate cell IDs and duplicate session IDs and canonicalizes the cell ordering.

3. **Plan-pinned statistics executable hash: PASS.** Formal plan validation requires a SHA-256 `statistics_executable_hash`; this value is included in the plan hash and formal launch binding. Joint issuance rejects a caller-supplied value different from the frozen plan, and the value is included in both the generation-wide HMAC body and each state-key-authenticated FINALIZE wrapper.

4. **Shared supervisor `joint_unseal_hash`: PASS.** Only after exclusive durable publication does issuance set the same `joint_unseal_hash` on every admitted supervisor. Each supervisor re-verifies the global HMAC and refuses any joint record whose hash is not the exact hash assigned during that single issuance. It then reopens the plan and barrier and checks generation, barrier, root hashes, complete cell set, its session, and its formal-binding hash before producing a one-use FINALIZE authorization.

5. **Adversarial coverage: PASS.** Tests explicitly cover an incomplete supervisor set, an alternate authorization path, a wrong plan-pinned statistics hash, a statistics/hash tamper with stale HMAC, duplicate issuance, a bad state-key wrapper HMAC, and cross-cell authorization. The assertions verify that no access seal, maturity ledger, or run seal is written on rejected paths.

## Additional release checks

- **Fail closed:** provider/evidence/schema/model/transport mismatches become closed errors or exact fallback. Invalid or unauthenticated formal FINALIZE requests are rejected before label-bearing writes.
- **No retry:** the production transport is single-use and has one static `HTTPSConnection.request` callsite outside all loops. HTTP redirect statuses, request exceptions, response exceptions, oversized bodies, and concurrent/second sends are terminal; receipts require `retries == 0` and at most one wire call.
- **Late handling:** a late response is durably classified but cannot enter the committed prediction. Runner logic commits the exact fallback, marks `late_response_ignored`, and the append-only ledger rejects overwrite/duplicate completion.
- **Secret persistence:** credentials are supplied only through a one-use in-memory lease, removed from headers, and the mutable lease buffer is wiped. Provider exceptions are neither stringified nor chained. Durable evidence contains typed hashes/counts, not raw response text, raw provider IDs, credentials, or Authorization headers. The secret-pattern scan found no Ark-style key; its sole Bearer-pattern file is the intentional synthetic canary test at `tests/test_vfps_ark_provider.py:692`.
- **Mock/offline boundary:** `ark_provider.py` has no network/environment client and accepts injected transport only. The explicit unsafe schema override is confined to offline fixtures; the formal adapter otherwise requires the canonical arm schema plus attested one-shot transport. A formal physical generation rejects mock/unattested outputs before label access. Architecture-registry validation is local and has no provider/network import.

## Residual non-blocking risks

1. This is deliberately an honest-launcher integrity layer, not a hostile same-UID/host filesystem security boundary. A malicious process able to mutate private Python supervisor state, signing keys, or ancestor path components remains outside the documented threat model.
2. M3.1 binds the frozen statistics executable hash but does not run statistics. The later scoring composition root must verify the actual executable bytes against that hash immediately before execution; this PASS does not certify a not-yet-implemented scoring entrypoint.
3. The transport receipt proves the local one-shot call path, not remote server receipt or execution. Server-side attestability remains unavailable and must not be claimed.
4. A crash after exclusive joint-artifact publication but before normal orchestration completes is fail-closed and may require abandoning/resealing the generation; this is an availability/recovery limitation, not an integrity bypass.
