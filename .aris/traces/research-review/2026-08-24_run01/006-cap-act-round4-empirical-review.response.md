## Executive assessment

The explicit pivot is correct. CAP-ACT no longer claims that per-origin IF syntax creates a new policy class, and it now frames typed authority, fallback, ledgers, and whole-policy qualification as the controlled architecture around an empirical question. That makes the proposal much more honest and potentially useful for PHM/industrial-AI audiences.

The revised 19-Action manifest fixes the previous RC1/ACT1 permission collision. RC1 now acts only on one outer-training-frozen \(b^\star(target,h)\); ACT1 is the literal union of 12 BaseActions and seven transforms of that same \(b^\star\); the 96-Action cross-product is correctly demoted to an appendix compositional-authority ablation. The revised IF count, \(19+225\times19\times18=76{,}969\), is also arithmetically correct, with an origin-specific quotient of 19.

Two scientific-design ambiguities must still be resolved before a real protocol is frozen: the proposal mixes a globally untouched shadow pool with LOCO training across that same pool, and the four-call block does not by itself identify model diversity separately from constituent-model ability. A smaller permission detail also remains: \(b^\star\) should be explicitly identical to the common FALLBACK/N0 champion, or FALLBACK/abstention permission must be aligned across subset arms before ACT1 is called their literal union.

These issues do not prevent planning or building a mock harness. They do prevent scientific execution and paper claims.

## 2. Revised 19-Action factorization: accepted with one identity condition

The revision now defines

\[
B=\{EMIT_1,\ldots,EMIT_6,FUSE_1,\ldots,FUSE_5,FALLBACK\},\qquad |B|=12,
\]

and freezes one \(b^\star(target,h)\in B\) using outer-training data only. The primary action set is

\[
A_{primary}=B
\cup\{SHIFT(b^\star,s):s\in S\}
\cup\{INFLATE(b^\star,q):q\in Q\},
\]

so

\[
|A_{primary}|=12+4+3=19.
\]

This is the correct minimal repair. H1 has six model actions, RF1 has five fusion actions, RC1 has the identity \(b^\star\) plus its seven transforms, and ACT1 exposes their finite union. Applying transforms to arbitrary BaseActions is correctly isolated as ACT-COMP96; ENUM-COMP96 and IF-COMP96 must remain paired appendix comparators.

One permission identity must be made explicit. If \(b^\star=FALLBACK=N0\), the subset union is exactly the 19-Action set. If \(b^\star\) is another EMIT/FUSE action, explicit FALLBACK is present only in ACT1 unless H1/RF1/RC1 also receive an abstention ID. Choose one of:

1. define \(b^\star\) to be the common FALLBACK/N0 champion; or
2. add the same explicit ABSTAIN/FALLBACK permission to every typed subset arm and account for its duplicate in the set cardinality.

Deliberate selection of FALLBACK must be recorded separately from error-induced fallback. The numeric bundle can be identical, but selected_abstention and execution_failure have different reliability interpretations.

The revised IF1 count is exact for ordered unequal branches:

\[
19+225(19)(18)=76{,}969.
\]

At a realized origin those syntactic programs quotient to 19 active Actions, as the proposal correctly states.

## 3. Exact SHIFT and INFLATE semantics

The proposed location shift is deterministic and preserves quantile order:

\[
\hat y'=\hat y+s\,scale_{train}(target,h),\qquad
Q'_\tau=Q_\tau+s\,scale_{train}(target,h).
\]

Before implementation freeze:

- the exact train-only residual-scale estimator, unit weighting, and hash;
- the rule for zero, missing, or nonfinite scale—prefer removing that transform from the manifest rather than failing unpredictably at runtime;
- unit and target/horizon specificity;
- physical-domain validity checks and the whole-bundle fallback rule;
- no post-result clipping or data-dependent repair.

INFLATE is also deterministic for each predeclared central interval:

\[
L'_\alpha=\hat y-q(\hat y-L_\alpha),\qquad
U'_\alpha=\hat y+q(U_\alpha-\hat y).
\]

It requires the base contract \(L_\alpha\le\hat y\le U_\alpha\), nested 50/80/90 intervals, finite values, and consistent target units before expansion. Apply the formula separately to each frozen interval pair, then verify nesting, quantile monotonicity, and domain constraints. If the point is outside a base interval or any pair is missing, reject the complete origin bundle.

INFLATE is uncertainty recalibration, not residual/location correction. Either name RC1 a bounded correction-and-calibration arm or report SHIFT and INFLATE choices separately. Do not infer a residual-correction mechanism from an interval-only action.

## 4. Packet parity, arm isolation, and common planned keys

The two-packet design is strong:

- D1-RAW is the required direct numeric LLM arm on raw causal information.
- D1-PACKET sees the same numerical candidates and train-only summaries as hybrid arms but retains free numeric output.
- Hybrid local execution occurs only after the provider response ends; it is not a hidden tool continuation.
- Each arm has a distinct response schema and exact fallback.

Required implementation constraints:

1. Keep D1-RAW and D1-PACKET prompts identical except for the added packet section and its necessary field description.
2. Use a compact fixed-order numeric vector or equally compact strict structure for direct arms; otherwise typed IDs receive a structural output-token advantage. This advantage may still be reported as architecture efficiency, but not ignored.
3. Hash and report packet data bytes, full request bytes, provider input tokens, requested output ceiling, actual output/reasoning tokens, local CPU, and end-to-end latency separately.
4. Direct arms must have no registry/tool handle, model ID execution path, repair parser, or second chance. Hybrid arms must be unable to emit arbitrary numbers.
5. Freeze the complete planned-key set before any arm call: origin, target, horizon, quantile levels, availability mask, and maturity rule. All arms receive the same keys in the same order.
6. An endpoint globally ruled unavailable is a protocol-level common NA, not an arm-selected forecast and not an arm failure. RUL_NA should sit outside the numeric Action count.
7. Every planned key remains in the intention-to-treat denominator. Report planned, matured, active, deliberate-abstention, error-fallback, and never-matured counts separately. Maturity is determined independently of arm output.

Active-only error may be a useful diagnostic but is selection-biased and cannot replace planned-denominator loss.

## 5. ENUM-ACTION audit

The revised global-backoff score fixes the previous all-infinity failure. It is online-label-blind if every mean, standard error, stratum, candidate, hyperparameter, and feature transform is derived only from allowed training/development units and sealed before qualification.

The executable policy should additionally freeze:

- the exact action manifest—prefer the same 19-Action primary manifest as ACT1;
- the deterministic map from OriginPacketHybrid to ENUM features, including missingness;
- per-unit macro loss before any cross-unit mean;
- cluster-level standard-error formula and minimum-unit rule;
- whether \(\kappa SE\) is a heuristic pessimism penalty or a prespecified confidence bound;
- complexity values for every Action;
- global backoff when the current stratum is unqualified;
- exact lexicographic argmin and action-hash tie;
- target×horizon factorization or a finite bundle-template manifest.

Calling it a “pessimistic selector” is correct unless a genuine confidence construction and registry-wide multiplicity rule are frozen. Qualification/shadow inference can validate the selected policy but cannot retroactively turn a development heuristic into a UCB.

ACT1 versus ENUM-ACTION compares two policy-building paradigms, not matched development compute. Report LLM prompt trials/human time/API calls and ENUM label use/CPU evaluations separately.

## 6. Budget and multi-call topology audit

### One-call block

N0 aside, all primary API arms can be matched at one physical attempt, no accuracy retry, common deadline, common data availability, and common requested ceiling. The proposal correctly separates requested-budget claims from actual-spend calipers and cost-quality Pareto analysis.

The experiment-specific accuracy_v1 contract must override the generic Gate-1 retry allowance. A second transport attempt is a second physical attempt even when the first request body was not fully sent.

### Four-call block

Treat all comparisons within a four-attempt envelope. Cross-envelope one-call versus four-call results are resource-response/Pareto results, not matched-call architecture effects.

Minimum repairs:

- Choose one exact direct-forecast aggregator. “median/trimmed” is not a specification; componentwise median with deterministic interval validation is sufficient.
- Define ACT4 selection exactly, for example plurality with a frozen train-risk tie and then action hash. If this adds no core claim, delete ACT4 from the first scientific package.
- D4-H uses stochastic repeats, not four independent physical units. The four outputs remain one origin-level cluster.
- D4-X versus D4-H is a heterogeneous-roster comparison. To claim diversity, run one-call performance for every constituent model and either homogeneous four-repeat controls for each constituent or restrict the conclusion to the sealed roster.
- Parallel D4 and sequential REFLECT have different attainable latency under the same deadline. Report wall time and deadline failures; do not call latency matched merely because both have four attempts.
- Sequential reflection accumulates previous-output input tokens. Its total input/output/reasoning budget must be included in the same envelope.
- Preseal the minimum D4-H/D4-X policies before inspecting one-call qualification results. If any multi-call prompt/roster/aggregator is designed after qualification, it needs new untouched qualification units.

D4-H/D4-X are more accurately described as multi-call forecast ensembles than as evidence of multi-agent reasoning. This is not a problem as a required control, but it limits the novelty language.

## 7. Qualification, shadow evaluation, and adaptive reuse

The proposal's development → qualification → final structure is principled. One ambiguity is scientifically material:

> A globally untouched shadow pool cannot simultaneously supply training labels for other shadow folds and remain globally untouched.

Choose one of two honest designs before data access:

1. **Fixed cohort split:** development and qualification units train/select everything; all shadow units are predicted without using any shadow label in any fit. This is a true untouched shadow test, but it is not LOCO over the shadow pool.
2. **Sealed outer cross-validation:** freeze the policy-development process first, then run all whole-unit outer folds once, allowing each outer-training set to include units that are tests in other folds. This is legitimate nested/outer CV, but call it sealed outer CV rather than a globally untouched shadow pool.

Do not combine the labels. In either design:

- fit numerical models, normalization, calibration, error summaries, bins, fallback, and action availability inside each allowed training set;
- keep every window from the held-out unit out of its fold's fit;
- freeze policy candidates and confirmatory contrasts before opening qualification results;
- run every final arm on the same fold/key manifest;
- aggregate origins within physical unit first and infer on paired unit-level differences;
- account for all confirmatory arm selection/multiple contrasts;
- do not treat API replicates or rolling origins as independent units.

The value/cost gate for the secondary block is safe only if the conditional run rule and all potentially activated policies are presealed. The proposal already says D4-H/D4-X remain minimum arms even after a negative pilot; make that unconditional in the registry to avoid selective omission.

## 9. Empirical novelty and minimum publication package

No independent literature search was permitted, so novelty remains unverified. As a reviewer inference rather than a literature claim, the broad category—“do LLMs/tools/agents help a domain task under controlled budgets?”—is already a crowded empirical template. Capacitor specificity alone will not create a strong paper. The defensible novelty must come from unusually clean factor identification, public auditable whole-unit replay, and a result that changes practice.

### Artifact report ceiling

The work remains an artifact/protocol report if any of the following is the maximum evidence:

- mock, synthetic, failure-injection, or Stress-2 results only;
- Benchmark-L structural parsing without eligible targets;
- one provider/model and one weak or unaudited fleet;
- only schema-validity/fallback gains;
- no strong numerical champion or no common-key planned denominator;
- no independent external stress and no unit-level uncertainty.

### Minimum credible PHM empirical package

At minimum:

1. Ren or another adequately sized primary fleet passes identity, chronology, target-derivation, duplicate, and split gates.
2. A strong inner-selected numerical registry/champion is evaluated on whole held-out units.
3. The complete one-call factorization and minimum D4-H/D4-X direct multi-call controls run on common planned keys.
4. Multiple authenticated backbones are represented, with requested/actual resource accounting and API replicates treated correctly.
5. Paired physical-unit effects, uncertainty, worst batch/protocol folds, interval quality, failure/coverage, and cost Pareto are all reported.
6. At least one independently audited external corpus or target-domain stress is included with honest target semantics.
7. The harness, schemas, manifests, compact predictions/ledgers, and claim matrix are reproducible.

A rigorous, well-powered null result can be publishable if it survives multiple backbones and credible external scope. A null on one fleet/model is a local engineering finding.

### Journal-level PHM/TII/TIM/MSSP positioning

For a strong journal submission, the safest minimum is one substantial primary fleet plus an independently audited external corpus with compatible target semantics, not merely a second table of overlapping units. Patrizi can be a useful cross-domain/confounded stress, but eight one-strategy-per-unit devices do not replicate within-condition generalization. Warwick has a different energy target. Neither should be presented as equivalent confirmation of Ren capacitance.

The paper would also need a domain-relevant finding beyond a leaderboard: for example, a stable boundary on when numerical candidate information, typed authority, or model roster helps or harms across horizon/protocol regimes. Which boundary exists is unknown until results are run.

Without a persistent-program/general mechanism and broader evidence, NeurIPS/ICML method positioning remains inappropriate. This statement is based on the local proposal and claim type, not an online venue survey.
